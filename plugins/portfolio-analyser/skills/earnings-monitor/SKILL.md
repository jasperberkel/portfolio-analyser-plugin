# Quartalsüberwachung

Use only the requesting person's private MCP connection. The analysis permission is required for changes. Never use another account's session or an operator credential. For setup call sync_earnings_tracking; Thomas binds the personal wake during setup and the service synchronizes successful imports against the latest snapshot. List with list_earnings_tracking. On Thomas, for a first explicit watch bind_personal_wake({"package":"portfolio-analyser"}) in the requesting private draft chat. For "beobachten"/"nur danach"/"einen Tag vorher" resolve an unambiguous stock (issuer key from the tracking list or issuer registry, otherwise `isin:<ISIN>` for a common-stock OpenFIGI lookup), then use set_earnings_tracking. Both modes record the preview. Removing a watch drops its explicit reason; muting also silences holdings. Confirm the resulting reasons and delivery mode by reading the list.

A host wake claims one due item with claim_due_earnings. Calendar work actively searches and opens the issuer IR calendar, release notice or regulator material through the isolated host, including for an unfamiliar stock. A configured feed is optional. It verifies issuer identity and identifies the actual reporting period, date certainty, source zone and earliest permitted window. An absent confirmed source is a dated gap. A shift revises the existing event. Use only an already encountered publication as published_notice. Never probe release sources on another day. The service admits at most one release probe per rolling hour on the issuer-local day. A probe claim authorizes one bounded host lookup for a release. Calendar work may record a release already encountered. A month or part of a month never authorizes a release probe. Revisit partial calendars relative to the beginning of the stated interval.

For preview, actual or revision use the [specialist](../earnings-analysis/SKILL.md) with the supplied event and dated evidence. On actuals validate candidates before reading a report. No match requires a reason. Persist with complete_earnings_check using the original claim and exact payload on transport retry. See the [wire contract](../../references/research/earnings-monitor.md). A one-off question never uses these writes.

Delivery is personal. Honor the returned delivery ID in the visible message. A previously started delivery may only be acknowledged with a verified receipt from the original destination; never repeat an uncertain send. Use a host with a verified personal destination and delivery recovery. Never substitute a shared chat.
