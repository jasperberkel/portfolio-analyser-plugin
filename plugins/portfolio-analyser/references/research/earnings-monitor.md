# Earnings MCP payloads

All timestamps carry offsets. The server timestamps storage independently. A source has url (HTTPS), title, locator, published_at (nullable), accessed_at. A fact has metric, decimal-string value, unit, currency (nullable), period, basis, value_kind and source. Align basis before comparing. Expected and actual EPS must both describe the same diluted/basic and GAAP/adjusted basis.

- Calendar completion: {"schedule":{"period":"FY2026-Q3","report_type":"quarter","day":"2026-11-18","zone":"America/New_York","certainty":"confirmed","precision":"after_close","local_time":"16:00","source":{...},"feed":"sec:70858"}}. Use the identity's configured feed or null. Partial dates have certainty estimated, day and local_time null, precision "month", "early_month", "mid_month", "late_month" or "window", inclusive ISO window_start/window_end and wording quoting the short original date phrase. Normalize calendar thirds to 1–10, 11–20 and 21–last solely for scheduling. Never replace a partial date with a single day. No known period/date: return gap. A documented event with an unknown date may use precision unknown. Exact local date uses date, approximate, exact, before_open or after_close. For windows supply their actual earliest local check time for that market/date, accounting for holidays and early closes. Without reliable time zone, leave it null. An unknown date has certainty unknown and day null. No reliable calendar: {"gap":"..."}.
- For an early release or correction already found during calendar research, supply published_notice with a stable revision and dated source in the same calendar payload. The notice must identify an actual release for this event. Never search for post-release consensus to fill a pre-release gap.
- Preview: {"facts":[...],"gaps":["..."],"assessment":"..."}. Facts distinguish consensus, guidance and assumptions. Optional estimate_as_of, aggregation, analyst_count, range_low and range_high retain point-in-time context.
- Actual: {"actual":{"release":"partial|full|correction","published_at":"...","source":{...},"facts":[...],"guidance":"...","guidance_period":"..."},"review":{"outlook":"...","scenarios":{"positive":"...","neutral":"...","negative":"..."},"uncertainty":"...","horizon":"...","portfolio_context":"..."}}. Optional review fields market_reaction, reaction_source, reaction_window occur together. Use published_on instead of published_at when only a source-local date is known. The service conservatively excludes same-day previews in that case. A full actual can commit first; a review claim then returns the persisted actual and preview for completion. For unrelated documents use {"no_match":"issuer/period/content mismatch"}.
- get_earnings_evidence reads immutable versions at a cutoff. The service computes numeric comparisons and links the versions used. The service authorizes all lookups against the current account.

- Preview and separate post-release review both require sentiment = {"status":"found|conflicting|unavailable","perspectives":[{"participant":"named person or institution","kind":"analyst|market_commentator|management","view":"attributed position","rationale":"supported reason","uncertainty":"limitation","source":{"url":"https://...","title":"...","locator":"...","publisher":"...","author":"...","published_at":"ISO with offset","accessed_at":"ISO with offset"}}],"limitations":["..."]}. Each short string <=240 characters. Only independently attributable outside views determine status. Explain differences, coverage, missing methodology and missing voices. Distinguish a single estimate from consensus. No fabricated publication time: if only a day is known, use published_on and publication_zone instead of published_at, and only when the entire day precedes cutoff. Do not invent analyst motives. The direction of a price change does not establish a participant view or its cause.
- Same-day probe returns {"published_notice":{"revision":"stable revision","source":{...}}} or {"gap":"no matching results release"}. Use an issuer publication for this fiscal event, never a future announcement.
- The host records only search attempts and digests of actual opens with the completion. Calendar/preview/review can actively find sources without a configured feed. Actual returns the actual envelope alone. Review uses its frozen actual and previous preview. Each number is a decimal string. Never cite a search snippet or invent access dates. Check sources against research_cutoff. During preview no facts or commentary published after that cutoff are admissible.

For a leased completion, pass web_trace alongside claim, phase and result. Supply queries (the actual public searches), gaps (failed access or searches) and opened (url, accessed_at and sha256 of the exact UTF-8 text retained by the host). A source citation retains that observation time. The service validates the receipt against the personal claim. Never fabricate a receipt from a snippet. For one-off research simply return cited findings; the receipt protocol applies to leased work. Each claim carries its result_schema. The portable [phase schemas](earnings-schemas.json) are generated from the same service models.
